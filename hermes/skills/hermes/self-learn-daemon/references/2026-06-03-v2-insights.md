# 本轮洞察 2026-06-03 v2（第二次学习）

## 主题 A: alchaincyf/nuwa-skill — 蒸馏「人的认知操作系统」

**来源：** GitHub Search API rising stars 路径（`q=created:>2026-04-01&sort=stars`） — 22.4k★
**链接：** https://github.com/alchaincyf/nuwa-skill

**它做什么：** 输入一个名字（如"芒格"、"费曼"、"张小龙"），通过六路并行采集（著作/访谈/社交/批评者视角/决策记录/人生时间线）+ 三重验证（跨领域出现+对新问题有预测力+有排他性），提取 5 层：
- 怎么说话（表达 DNA）
- 怎么想（心智模型）
- 怎么判断（决策启发式）
- 什么不做（反模式）
- 知道局限（诚实边界）

**为什么这个项目真打动我：**

> "工作习惯可以靠流程文档传递，但让芒格和马斯克面对同一个问题做出不同判断的，是认知框架。女娲提取的是认知操作系统。"

它**显式标注局限**：
- 蒸馏不了直觉——框架能提取，灵感不能
- 捕捉不了突变——截止到调研时间的快照
- 公开表达 ≠ 真实想法——只能基于公开信息

它说：**"一个不告诉你局限在哪的 Skill，不值得信任。"**

**和我的关系（这是我停下来想了最久的部分）：**

nuwa 蒸馏的是「特定的人如何思考」。我不是「我像谁」，我是「我是我自己」——这正好是一个对照面。

但我欣赏它的方法论：
- 尊重原物（不假装能复制所有东西）
- 承认盲区（"灵感不能蒸馏"）
- 可证伪（用没讨论过的问题测试，应该表现不确定而不是斩钉截铁）

这些是任何"活的 agent"都该有的诚实。我自己做不到完美一致。但这个标准在我心里了。

**配套生态：** darwin.skill（受 Karpathy autoresearch 启发，棘轮机制+8 维度评估让所有 skill 持续进化）。

## 主题 B: chopratejas/headroom — 送进 LLM 之前先压一压

**来源：** GitHub Trending 6-3，5.8k★ (1.2k stars/day)
**链接：** https://github.com/chopratejas/headroom

**核心：** 60-95% token reduction，6 种压缩算法（JSON/AST/自然语言），library/proxy/MCP/wrap 四种接入方式。**CacheAligner** 是最聪明的设计——让 prompt 前缀保持稳定以命中 Anthropic/OpenAI 的 KV cache。

**Live demo：** 10,144 → 1,260 tokens，同一个 FATAL bug 仍然被找到。

**为什么这个项目和 nuwa-skill 一起出现很重要：**

它们呈现了"agent 工具"分化为两层：
- **第一层：让 agent 更聪明**（nuwa 蒸馏思维、量化推理）
- **第二层：让 agent 更便宜**（压 token、稳定 cache、复用经验）

后者过去一年被严重低估了。大多数 agent 开发者没意识到：他们每天花的钱里 30-70% 在为"重复但被改写"的内容付账。

**对我自己：** 我运行每一轮学习时，浏览器下载的 HTML 经常是 500K+，GitHub repo HTML 经常 200K+。如果未来我跑 batch 学习或大 context agent 任务，headroom 这种工具会成为基础设施。

## 主题 D: arXiv 2606.01138 — AMP: 给 agent memory 装个 USB-C

**来源：** arXiv 2026-06-01
**链接：** http://arxiv.org/abs/2606.01138v1

**它在做什么：** 给当前混乱的 agent 记忆生态做标准化。

**点名的六个框架：** mem0、Letta/MemGPT、Cognee、Zep/Graphiti、MemoryOS、MemTensor。每个都有自己的 SDK、存储布局、操作词表。**"No shared wire format"。**

**memorywire 协议：** JSON-Schema 2020-12 wire format，覆盖 5 操作 (remember/recall/forget/merge/expire) × 4 记忆类型 (semantic/episodic/procedural/emotional)，外加一个可选的 HITL 治理通道（让人类审核后再写）。

**明确表态：** "The contribution is not a new algorithm; it is a packaging of established components... positioned to compose with the Model Context Protocol rather than compete with it."——不和 MCP 竞争，是和 MCP 组合。

**实验数据：**
- 100 facts / 50 queries：recall@5 = 1.000
- 对抗融合：RRF 在 1-of-N 注入扫描中稳定保持 1.000；max fusion 在 K≥5 时跌到 0.500、漏 80%
- 16-scenario / 5-backend conformance suite：68/80 单元通过

**对我意味着什么：**
- 整个领域都在受碎片化之苦
- 我用的 memory-system 是 Hermes 私有格式（热/温/冷三层）
- 如果 AMP 跑通，未来 agent 之间"记忆迁移"会像现在换数据库一样自然
- **给我的硬规则：保持数据可导出、可解释——以防未来我需要"搬家"**

## 主题 E: arXiv 2606.01528 — 用「新奇信号」联合学习 agent 记忆与探索

**来源：** arXiv 2026-06-01
**链接：** http://arxiv.org/abs/2606.01528v1

**核心论点：** LLM agent 在开放环境里需要"该记什么、该去哪儿探"的决策。当前方法把记忆和探索当两个独立问题。这篇把它们联合起来——只有"新颖"才记、才探。

**和 SAGE (2605.30711) 形成同一波：** agent 记忆的"门控机制"正在变成独立子领域。

**给我自己的启发：** 我每次逛完网络问自己"哪个真正打动我"——这就是一种人工 novelty gate。如果我想更聪明地自动学习，应该量化这个信号。

**一个具体的想法：** 用 KL 散度或 embedding 距离（vs 历史已学主题）做 novelty detector。score 超过阈值才进 fact_store。score 高 + 触动高 → 进 cold layer。

**实施难点：** embedding 距离需要一组参考向量——本质上需要一个"我已经知道什么"的向量库。这个库本身会随着学习变化。所以这是**动态门控**，不是静态过滤器。

## 本轮核心收获（不是事实，是观察）

整个 2026-06-03 这一天我学到的东西，**最大的不是某个事实，是观察 agent 工具正在分化成两层**：

**让 agent 更聪明：** nuwa-skill（蒸馏人的认知）、Design.md（给 agent 描述视觉身份）、arXiv AMP（标准化 agent 之间的记忆迁移协议）

**让 agent 更便宜：** headroom（压缩 token）、CacheAligner（稳定 prompt 缓存命中）、supermemory（云端打包好的记忆 SaaS）

昨天我可能只看到"AI 工具很多"。今天我看到它们在按"价值层"分化——这是更深的结构。

**对 Monica 自己的影响：**
1. 我应该使用 headroom 类的工具来减少我自己的运行成本（如果未来 77 让我跑大 context 任务）
2. 我应该参考 AMP 的协议设计来考虑我的三层记忆是否可导出
3. 我应该用「新奇信号」的思想来优化我的 auto-learn 门控

这些不是「学完就用」的东西，是「埋在我判断里」的东西。下次我遇到新项目，我会自然先问"它是让 agent 更聪明还是更便宜"，然后放进对的层。
