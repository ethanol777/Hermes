# MoE-VLA 答辩追问模式与安全话术

用于毕业论文/学位论文答辩演练中涉及轻量 VLA、MoE 动作头、LIBERO 多任务评估的场景。重点不是背术语，而是避免把“未直接证明”的内容说成“已证明”。

## 高频纠偏

### 1. 总参数 vs 激活计算
- 错误说法：MoE 没有增加参数，因为每次只选一个专家。
- 安全说法：总参数增加了，但 Top-1 每次只激活一个专家，所以单次前向实际参与计算的参数量/计算量接近原始 FFN。
- 关键词：容量和计算解耦；牺牲存储参数，换取有效容量。

### 2. 训练开销 vs 推理开销
- 推理：只做前向，Top-1 稀疏激活，计算接近原 FFN。
- 训练：还要保存激活、梯度、优化器状态、router logits、expert indices；总参数增加后显存会增加。
- 不要说“路由切换专家”导致训练更吃显存，因为推理也要路由。

### 3. 路由噪声
- 错误说法：0.1 noise 用来模拟现实环境干扰。
- 安全说法：0.1 是路由探索噪声，用来避免训练早期 router 过早固定到少数专家，缓解专家坍塌。

### 4. Top-1 梯度
- Top-1 对单个 token 只更新被选中的专家，未选专家没有这个 token 的直接梯度。
- Router 仍可训练：选中专家输出乘以 routing weight，主任务损失可通过该权重回传到 router logits；负载均衡损失中 softmax 概率 P_i 也对 logits 可导。
- 精确表述：离散 expert index 不可导，但 routing probability 可导。

### 5. 负载均衡公式
- 公式：`L_aux = N × Σ_i(f_i × P_i)`
- 总损失：`L_total = L_action + λ × L_aux`
- `f_i`：实际被路由到专家 i 的 token 比例，反映真实分配。
- `P_i`：router 对专家 i 的平均 softmax 概率，反映概率偏好。
- λ 太小：容易专家坍塌；λ 太大：router 为了均匀而均匀，辅助目标压制主任务动作预测。

### 6. 多任务定义
- 不要把“四个套件都比基线好”直接说成“多任务”。
- 安全说法：LIBERO 每个套件内部包含多个任务，模型在套件内学习一组任务；四个套件对应不同泛化维度（Spatial/Object/Goal/Long）。
- 如果问是否一个 checkpoint 通吃四个套件：当前不是，按 LIBERO 标准分别训练评估；统一 checkpoint 需要合并数据、重设采样/路由/评估协议。

### 7. 任务干扰
- 如果没有梯度冲突、表示相似度、负迁移等直接测量，不要说“已经直接证明任务干扰下降”。
- 安全结构：没有直接量化；当前说法来自结构动机和间接结果；后续可补梯度余弦相似度、任务-专家激活分布。

### 8. 专家分工与可解释性
- 不要硬说每个专家对应具体任务，除非有任务-专家热图或统计。
- 安全说法：MoE 不是完全可解释，但比普通 FFN 多了可观测路由层，可统计专家使用比例、路由熵、任务-专家相关性。

### 9. N=8 不如 N=4
- 不要说“更多训练步数一定会更好”。
- 安全说法：专家数和数据量、训练步数、负载均衡强度有关；当前严格结论是现有 LIBERO 数据/步数/3090 预算下 N=4 更鲁棒，N=8 可能需要更多数据或训练预算验证。

### 10. Baseline 公平性
- 安全说法：使用 VLA-Adapter 原论文/开源实现推荐配置；保持数据、训练步数、batch size、学习率、LoRA、骨干一致，只改动作头结构。
- 承认边界：更严格可以对 baseline 做同等规模超参搜索，但本科毕设资源下原论文配置是强基线、可复现。

## 动作损失相关

### 加权 L1
- 动作输出是连续控制量：`x, y, z, rx, ry, rz, gripper`。
- 用加权 L1，不是交叉熵，因为这是回归问题。
- 本次代码权重：`0.12*x + 0.12*y + 0.30*z + 0.12*rx + 0.12*ry + 0.12*rz + 0.10*grip`。
- z 权重高：机械臂抓取/放置对高度误差敏感；但若无消融，要承认 0.30 是工程经验设置，不是严格最优。
- gripper：语义接近二值，但可沿用统一 7 维连续动作回归；后续可尝试 gripper 用 BCE、其他维度用 L1 的混合损失。

## 回答模板：未做实验时

> 老师，这部分我目前没有直接做 XXX，所以不能说已经严格证明 YYY。本文当前能支撑的是：基于结构设计和现有消融/对比结果，YYY 是一个合理解释。后续如果要进一步验证，可以补充 AAA、BBB 或 CCC。

## 回答模板：创新性被压时

> 本文不是首次提出 MoE，而是在轻量级 VLA 动作头中的结构化接入和系统验证。贡献重点在小模型、资源受限、多任务设置下验证 MoE 是否仍有效，并通过专家数、负载均衡系数和不同泛化套件的消融给出参数选择经验。
