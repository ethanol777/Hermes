# 2026-05-20 MoE-VLA 答辩演练要点

## 用户偏好与流程
- 如果项目目录已有 `答辩问答演练.md`，先视为当前问答知识库：不要重复问里面已经覆盖充分的问题，除非是更深一层追问。
- 用户偏好“评委式压力提问 + 回答后立刻打磨 + 同步追加到文档”。不要只口头演练。
- 用户说“不知道/不清楚”时，不要让他硬编；给安全边界话术：承认未做直接验证 + 说明已有间接证据 + 给后续补充方向。

## MoE-VLA 常见答法边界

### 总参数 vs 轻量化
错误答法：没有增加参数，因为每次只选一个专家。
正确答法：总参数增加，但 Top-1 每次只激活一个专家，所以前向实际计算量接近原 FFN。轻量化指推理激活计算和资源预算，不是总参数完全不变。

### MoE vs Dense FFN
核心词：容量和计算解耦。
Dense FFN 扩宽会让容量、显存、计算量同步增加；MoE 牺牲一部分存储参数，通过 Top-1 稀疏激活在相近计算预算下增加有效容量。

### N=8 不如 N=4
不要说“更多训练步数一定更好”。更稳：N、训练数据量、训练步数、负载均衡强度需要匹配。当前实验严格支持的是：在 LIBERO 当前数据规模、训练预算和单张 3090 条件下，N=4 最鲁棒；N=8 可能需要更多步数/数据/路由策略才能验证容量优势。

### 专家分工与可解释性
不能硬说“已经证明每个专家对应具体任务”。安全说法：目前有专家使用比例、路由熵、消融结果等间接证据；MoE 相比普通 FFN 多了可观测和可干预的路由层，提供分析任务分工的接口，但完整任务-专家热图是后续工作。

### 多任务定义
不要把“四个套件都比 baseline 好”直接等同于多任务。更准：LIBERO 每个套件内部包含多个操作任务，模型在套件内多任务训练/评估；四个套件分别验证 Spatial/Object/Goal/Long 不同泛化维度。本文不主张一个 checkpoint 同时覆盖四个套件。

### 任务干扰
router noise 0.1 不是现实干扰，而是路由探索噪声。不能用它证明任务干扰被测量。正确说法：没有直接测梯度冲突；“缓解任务干扰”来自结构动机和间接实验结果，后续可补梯度余弦相似度、任务间负迁移、任务-专家激活分布。

### 负载均衡损失
作用对象是路由分布，不是“规范专家”。λ 太小：大量 token 集中到少数专家，其他专家闲置，发生专家坍塌。λ 太大：路由器为了均匀而均匀，负载均衡目标压过主任务动作预测，可能把 token 分给不合适专家，性能下降。

### Long 套件难点
不要只说动作更长。Long 难在长时序组合：子步骤依赖、误差累积、视觉状态持续跟踪、语言目标保持、动作输出连贯；MoE 还要保持相邻时间步路由稳定性。

### 动作头定位
视觉和语言部分解决“看懂、听懂”，动作头解决“怎么做”。多任务冲突主要体现在动作映射阶段：不同任务可能共享相似感知/语义，但动作分布差异大。
